# Dororong 제품 셸 설계

상태: 2026-09-11 채팅에서 설치형·런타임 포함 방향 및 이 세부 설계 승인(ㄱㄱ).
기능 기준: 18b6e4a 및 이후 회귀 테스트 보강. 계획 원장은 TASKS.md만 사용한다.

## 1. 범위와 구현 순서

첫 단계는 기존 WPF 앱 안에 제품 관리 계층을 추가하는 것이다. 제품 이름,
단일 실행, 관리용 트레이, 로컬 오류 로그만 담당한다. 별도 백그라운드 프로세스,
서비스, 네트워크 연결, 자동 업데이트는 만들지 않는다.

두 번째 단계는 이 셸을 사용하는 사용자별 설치·업그레이드·제거 패키지다.
Windows x64용 .NET 런타임을 포함하고 관리자 권한을 요구하지 않는다.
이번 문서는 첫 단계의 구현 승인 기준이다. 실제 설치 패키지의 파일 교체와
제거 방식은 셸 검증 후 별도 설계한다. 공개 배포/서명은 자동으로 승인되지 않는다.

### 검토한 구조

- **선택: 기존 앱 + 분리된 제품 셸.** 캐릭터 엔진은 그대로 두고 앱 생명주기에
  관리 기능을 붙인다. 프로세스 간 통신과 별도 업데이트 서비스가 필요 없다.
- MainWindow에 관리 기능을 직접 추가하는 방식은 시작/종료 책임과 캐릭터
  창 책임이 섞이므로 선택하지 않는다.
- 외부 런처/서비스가 앱을 관리하는 방식은 첫 배포에 불필요한 프로세스와
  복구 경로를 늘리므로 선택하지 않는다.

## 2. 제품 표시

- 표시 이름: **도로롱 (Dororong)**. 배포 실행 파일: **Dororong.exe**.
- 최초 제품 버전: **0.1.0**. 회사/게시자 메타데이터: **JOEWRKS**.
- 기존 캐릭터 리소스를 앱/트레이 아이콘으로 변환하되 원본 PNG나 모션 뱅크는
  수정하지 않는다. 아이콘은 별도 산출물이며 새 그림을 생성하지 않는다.
- 내부 어셈블리 이름 Dororong.App.dll, 네임스페이스와 WPF pack URI는 유지한다.
  게시 단계에서 네이티브 apphost만 Dororong.exe로 이름을 바꾸고, apphost가
  기존 DLL을 정상적으로 로드하는지 패키지 실행 테스트로 확인한다.
- 게시 폴더에는 제품 실행 파일 하나만 둔다. 개발 빌드의 Dororong.App.exe는
  유지할 수 있지만 제품 설치 바로가기는 Dororong.exe만 가리킨다.
- DesktopMetadataReader의 기존 자기 앱 제외 규칙은 기존/새 실행 파일 이름
  모두를 인식한다. 일반 WPF 앱 전체를 제외하지 않는다.

## 3. 실행 소유권과 종료

시작 시 진단 로거를 준비하고, 사용자 SID가 포함된 버전 독립적인 Local 이름의
named mutex를 비차단으로 확보한다. 범위는 같은 사용자·Windows 로그인 세션이다.
새 버전과 이전 제품 버전이 같은 이름을 사용한다.

- 첫 프로세스만 창/루프/트레이를 만든다.
- 두 번째 실행은 창·트레이·메시지 상자를 만들거나 기존 앱의 위치/입력 상태를
  변경하지 않고 종료 코드0으로 끝난다. 중복 실행을 오류로 기록하지 않는다.
- 종료 시 소유한 mutex만 원래 UI 스레드에서 해제하고 핸들을 닫는다.
- 비정상 종료 후 abandoned mutex를 확보하면 새 소유자로 계속 시작한다.
- 접근 거부 등 소유권 판정 자체가 실패하면 진단/오류 안내 후 종료한다.
  중복 실행을 허용하는 쪽으로 실패를 숨기지 않는다.
- 단일 실행 장치가 없는 기존 개발판을 자동 강제 종료하지 않는다. 최초 제품판
  시험 실행 전 기존 개발판은 명시적으로 종료하는 인계 절차를 사용한다.

기존 AppStartupSequence/FatalBoundary/OneShotOperation의 한 번만 실행되는
시작·오류·정리 계약을 유지한다. 트레이 종료와 캐릭터 우클릭 Exit는 동일한
MainWindow.Close → 앱 종료 경로를 탄다. 셸 정리는 중복 호출에도 안전해야 한다.
부분 초기화 실패도 이미 만든 자원을 정리하며, 정리 실패가 나머지 정리를 막지 않는다.

## 4. 관리용 트레이

기존 WPF Dispatcher에서 Windows Forms NotifyIcon을 감싼 TrayService를 소유한다.
별도 메시지 루프나 캐릭터 애니메이션 타이머를 추가하지 않는다.

메뉴는 다음 세 항목만 제공한다.

1. 도로롱 0.1.0 — 비활성 버전 표시.
2. 로그 폴더 열기 — 현재 사용자의 고정된 앱 로그 경로만 탐색기로 연다.
3. 종료 — 기존 정상 종료 경로로 전달한다.

트레이에 일시정지, 숨기기, 자동 시작, 앉아, 재시작을 추가하지 않는다.
기존 캐릭터 우클릭의 앉아/Exit와 머리 드래그 해제 동작은 유지한다.
트레이 표시/툴팁/두 번째 실행이 캐릭터 창을 활성화하지 않아야 한다.
앱 종료 시 아이콘 표시를 해제하고 NotifyIcon, 메뉴, 아이콘 자원을 해제한다.
초기 트레이 생성 실패는 시작 실패로 정리한다. 관리 아이콘 없이 새 제품판을
몰래 계속 실행시키지 않는다. Explorer 재시작 후 아이콘 복귀는 실사용 검증 항목이다.

## 5. 오류 로그와 개인정보 경계

경로는 Environment.SpecialFolder.LocalApplicationData 아래 JOEWRKS/Dororong/logs다.
일반 시작/정상 종료와 시작·루프·Dispatcher·정리 오류만 기록한다.
매 프레임이나 포인터 이벤트를 기록하지 않는다.

- UTF-8, 파일당 최대1MiB, 현재 파일+이전2개까지 순환 보관한다.
- 레코드는 UTC 시각, 제품 버전, PID, 정해진 이벤트/단계 코드, 예외 타입,
  HResult와 메서드 이름만 담는다. 긴 레코드는 크기 제한 안에서 잘라낸다.
- 예외 원문 Message/ToString, 사용자 파일 경로, 창 제목/내용, 검색어,
  키 입력, 마우스 좌표, 스크린샷을 저장하지 않는다. 원격 전송도 없다.
- 디렉터리 생성/쓰기/순환 실패는 캐릭터 실행이나 기존 오류 정리를 막지 않는다.
  로거 실패를 로거에 다시 기록하는 재귀 경로를 만들지 않는다.
- 기존 fatal 메시지 상자와 종료 코드1은 유지한다. 앱/창의 중첩 오류 보고는
  기존 one-shot 경계를 존중하고 로깅을 이유로 오류 대화상자를 늘리지 않는다.

## 6. 책임과 연결 지점

src/Dororong.App/Product 아래의 제품 관리 코드가 다음 책임을 나눠 가진다.

- ProductIdentity: 표시 문자열, 제품 버전, 사용자별 경로, 실행 파일 이름.
- SingleInstanceLease: OS 소유권 확보와 해제. 창/캐릭터를 참조하지 않는다.
- DiagnosticLog: 제한된 형식/크기의 로컬 로그와 회전. UI를 참조하지 않는다.
- TrayService: 트레이 자원과 두 명령 콜백. PetLoop를 직접 호출하지 않는다.
- ProductShell: 위 자원의 생성/정리 순서. App.xaml.cs에서 소유한다.

App.xaml.cs는 첫 창 생성 전에 단일 실행 판정, 시작 성공 시 트레이 연결,
OnExit에서 셸 정리를 맡는다. MainWindow.xaml.cs는 기존 fatal 경계에 제한된
진단 콜백을 연결하는 것 외에 입력/플랫폼/모션 제어를 바꾸지 않는다.
UseWindowsForms를 추가하더라도 암시적 Forms/Drawing using이 기존 WPF 타입을
모호하게 만들지 않도록 프로젝트 using 경계를 명시한다.

## 7. 검증과 전달 기준

구현 전 실패하는 테스트를 만들고 아래 동작을 순서대로 검증한다.

- 실제 named mutex를 사용하는 별도 시험 프로세스: 동시 두 실행 중 하나만
  소유, 첫 소유자 종료 후 재확보, 비정상 종료 복구, 비소유자 해제 안전성.
- 셸 수명주기: 중복 실행에는 창/트레이 생성0회, 초기화 각 단계 실패에도
  소유 자원 정리, 양쪽 종료 명령에서 같은 창 닫기, 반복 정리 안전성.
- 임시 디렉터리의 실제 로그: 크기/파일 수 상한, 회전, 원문 민감 문자열 제외,
  쓰기 불가/잘못된 경로에서도 앱 오류 경로 보존. mock 호출만 검사하지 않는다.
- 트레이 명령/정리와 실제 NotifyIcon 경계 검사. Explorer 복귀, 메뉴 동작,
  종료 후 아이콘 잔상은 실제 Windows에서 확인하고 자동 테스트와 구분한다.
- 배포 실행 파일의 이름/아이콘/메타데이터, DLL 로딩, 새/기존 자기 앱 제외 규칙.
- Core/App 전체 Release 회귀, win-x64 게시물과 테스트 DLL 대조, 모션 뱅크
  SHA256 불변, 기존 도약/걸침/앉기/수면/볼/머리 입력 검증.

첫 전달은 새 디렉터리의 셸 통합 후보로 한다. 현재 실행 중인 개발판, 기존
후보/로그/문서를 덮어쓰지 않는다. 실제 사용자 설치, 자동 시작 등록, 서명,
원격 업로드/푸시는 별도 인계 경계다. 이후 설치 패키지는 관리자 권한 없이
사용자별 설치, 런타임 포함, 시작 메뉴/앱 제거 등록, 새 설치 파일을 통한
업데이트, 자동 시작 기본 꺼짐이라는 승인된 방향을 따른다.
