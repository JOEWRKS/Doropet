# 창 가장자리 앞발 걸치기와 절전 복귀 복구

상태: 상세 설계 사용자 `ㄱㄱㄱ` 승인. 실행 계획/분리 검증 단계. 앞발 자세 미리보기의 별도 시각 승인 전 제품 적용 금지는 유지한다. Commit/push 승인 없음.

## 목표 / 기준

창 또는 보이는 수평 작업표시줄 윗선 가까이 도로롱을 끌어다 놓으면, 얼굴과 앞발이 드러나고 몸통은 뒤에 숨은 듯 걸친다. 기존 발로 서기·높이 비례 착지·일반 엉덩이 당김·볼과 다리 조작은 보존한다.

기준은 HEAD `87e7bb20aee925abcee135703bde46482d136f49`만이 아니라 현재 미커밋된 height-scaled-landing 제품 상태까지 포함한다. 기존 source/art/saved runtime을 보존한다. 기록은 TASKS.md 단일 원장을 사용하며 자동 commit은 하지 않는다.

절전 문제는 별개의 복구 경로다. 이전 분석에서 확인한 것은 '기존 작업표시줄 아래 상태가 유지되고 Reset으로 회복되는 메커니즘'이다. 실제 절전 사건의 최초 트리거를 확정하거나 해결했다고 아직 주장하지 않는다.

## 접근 선택

권장: 현재 하나의 투명 캐릭터 창 안에서 걸침 전용 표현과 투명 가림을 사용한다. 앞발 접촉점을 지지 기준으로 사용하고, 숨긴 몸의 입력 판정도 제거한다. 다른 앱을 수정하거나 화면 이미지를 복사하지 않는다.

대안1: 캐릭터 전체를 상대 창 뒤로 보낸다. 얼굴/앞발까지 가려지고 작업표시줄과 순서가 경쟁하므로 선택하지 않는다.

대안2: 얼굴·앞발과 몸을 서로 다른 네이티브 창으로 분리한다. 별도 좌표/포커스/입력 동기화 비용이 크므로 첫 버전에서는 선택하지 않는다.

## 사용자 동작

| 상황 | 결과 |
|---|---|
| 윗선 위에서 놓음 | 기존 낙하·발바닥 착지 |
| 전체 이동 드래그 후, 앞발 걸침 기준점이 윗선 바로 아래에서 놓임 | 짧은 붙기 전환 후 앞발로 걸침 |
| 볼/다리/배 등을 제자리에서만 당겼다 놓음 | 기존 국소 상호작용 복귀; 걸침 없음 |
| 걸친 캐릭터의 보이는 부분을 다시 드래그 | 먼저 걸침 해제, 같은 화면 위치에서 기존 직접 조작 인계 |
| 받치는 창 이동 | 창에 대한 가로 상대 위치와 앞발 접촉 유지 |
| 창 닫힘·최소화·접촉 구간 가림·유효 폭 소실 | 걸침 해제 후 실제 표시 위치에서 낙하 |
| 작업표시줄 자동 숨김 | 걸침 해제; 화면 바닥으로 낙하. 숨은 선에는 매달리지 않음 |
| 절전 후 의도 없이 작업표시줄 아래에 끼임 | 오류 복구; 새 걸침으로 승격하지 않음 |

첫 버전은 수평 윗선만 지원한다. 옆면/아랫면 매달림, 자율 기어오르기, 걸친 채 걷기, 기존 엉덩이 대롱대롱 버전 복원은 제외한다.

## 걸침 판단과 상태 소유

- 기존 직접 조작이 전체 이동 단계에 들어갔다는 사실과 실제 버튼 해제 이벤트가 있어야 후보를 선택한다. 이전 프레임 잔상이나 절전 복귀를 해제 이벤트로 만들지 않는다.
- 머리/볼/몸 중 무엇을 잡았든 최종 화면상 걸침 기준점으로 판정한다. 마우스 위치 자체를 앞발 좌표로 사용하지 않는다.
- 초기 후보 띠는 윗선 아래0~20 DIP, 붙기 전환은160ms로 제안한다. 물리 화면 좌표를 현재 모니터 배율로 변환한 뒤 판정하며, 수치는 첫 시각/체감 검토에서 조정 가능하다.
- 두 앞발 접촉 폭이 동일한 보이는 지지 구간 안에 들어가야 한다. 잘린 구간을 가로질러 붙지 않는다. 머리를 화면 안에 표시할 수 있어야 한다.
- 여러 후보가 있으면 가려지지 않은 유효 후보 중 세로 거리, 앞쪽 창 순서, 안정된 식별자 순으로 한 개만 고른다. 화면 바닥은 걸침 후보가 아니다.
- 직접 조작 → 붙기 → 걸침 → 직접 조작 또는 낙하를 명시한다. 붙기/걸침 동안 기존 발바닥 물리와 자율 이동은 위치를 갱신하지 않는다.
- 접촉 기준은 발바닥이 아니라 전용 앞발 지지점이다. 숨겨진 몸통의 아래쪽 alpha나 잘린 렌더 결과를 발바닥으로 재측정하여 물리에 되먹이지 않는다.
- 창 식별자와 generation, 모니터, 창 내부 가로 오프셋, 유효 접촉 구간을 보관한다. 식별자가 재사용되면 오래된 걸침을 인계하지 않는다.
- 짧은 장면 읽기 실패에는 마지막 표현을 잠깐 유지하되 기존500ms 만료 한계를 넘기면 오래된 창 부착을 해제하고 모니터 바닥을 안전 경계로 사용한다.

## 앞발/얼굴 표현

먼저 제품과 분리한 걸침 자세 미리보기1개를 만든다. 승인된 머리/얼굴/머리카락/장미/리본은 원본으로 고정하고, 걸침 앞발 형상과 접촉점만 명시적으로 제안한다. 기존 파트명은 해부학적 정답으로 취급하지 않는다. 새 자세의 파트 선택과 마스크를 공개하며 원본 Assets를 덮어쓰지 않는다.

얼굴은 윗선 위에, 앞발은 선을 짚고 발끝만 살짝 앞쪽으로 내려오게 한다. 몸통·뒷다리는 그리지 않는 투명 영역으로 처리한다. 하얀 사각형이나 대상 창 색을 덮어 숨기지 않는다. 발끝이 단순 직선으로 잘려 보이지 않아야 한다. 과거 실패처럼 머리 크기/모양을 새로 생성하지 않는다.

최종 렌더 alpha와 입력 판정을 일치시킨다. 숨긴 몸을 클릭하면 뒤의 원래 앱으로 전달되어야 한다. 표시 순서는 걸침 시작/복귀 검증 같은 제한된 시점에 자기 캐릭터 창만 비활성 방식으로 확인·보정하는 방안을 검증한다. 매 프레임 최상위 경쟁, 다른 앱의 Z-order/포커스 변경은 금지한다.

## 절전 복귀와 관통 복구

- 실제 복귀 경계의 native 좌표, 장면 건강 상태, 실제 표시 접촉점, 물리 상태/지지 키, 자기 창의 표시 순서를 제한된 진단 기록으로 확인한다. 창 제목·내용·전체 화면 캡처는 수집하지 않는다.
- 긴 프레임 공백과 실제 전원/디스플레이 알림은 재검증 계기로만 사용한다. 공백만으로 임의 위치 이동이나 걸침 생성은 하지 않는다.
- 재검증 중 잘못된 지지 정보/낙하 누적치를 다음 상태로 이어가지 않는다. 실제 표시 위치를 기준으로 재판정한다. 표시된 작업표시줄과 관통한 일반 상태는 유효한 윗선 위로 회복하되, 위쪽의 다른 창에 정상 지지된 상태를 끌어내리지 않는다.
- 복구 이동을 낙하 높이로 세지 않고, 가짜 강한 착지/두 번 반동을 만들지 않는다.
- 명시적으로 걸친 상태였다면 동일 유효 창과 접촉 구간을 재검증하여 유지할 수 있다. 일반 상태가 잘못 아래에 있다는 이유로 걸침 상태를 새로 만들지 않는다.
- 실제 전원 전환을 자동으로 강제하지 않는다. 모의 회귀 성공과 실제 절전 복귀 성공은 별도 판정으로 보고한다.

## 구조 / 검증 경계

입력 해제 의도, 접촉 후보 선택/상태 전이, 표시 마스크/앞발 기준, 복귀 재검증을 나눈다. 기존 DesktopScene/PlatformGeometry/SurfaceKey는 재사용하되 PetLoop의 위치 작성자는 계속 하나로 유지한다.

자동 검사에는 해제 의도 유무, 임계 띠 안팎, 재잡기, 빠른 드래그, 국소 조작 제외, 가려진 폭, 창 이동/리사이즈/소멸, 모니터 배율/제거, taskbar 숨김/복귀, 장면 실패, 렌더 마스크와 hit-test 일치, 기존 착지와 중복 실행 금지를 포함한다. 실제 WPF 표시기와 HWND 기반 검사를 포함하고 고정 사각형 검사만으로 끝내지 않는다.

시각 검토는 머리 동일성, 앞발 접촉, 테두리, 양쪽 방향, 붙기/떨어지기 전환을 제품 적용 전에 확인한다. 코드 통과를 미술 승인으로 확대하지 않는다. 절전 문제는 실제 복귀 관찰 전까지 완전 해결로 보고하지 않는다.

## 순서 / 인계

1. 사용자 상세 설계 검토.
2. 승인 후 실행 계획 작성. 기존 증거/소스/승인 자산을 동결하고 테스트 우선으로 진행.
3. 걸침 자세 미리보기와 복귀/상태 동작 검증을 분리. 그림은 사용자 검토 전 최종 승인하지 않음.
4. 검증·코드 검토 후 별도 실행본으로 체험 인계. 기존 실행본과 저장 버전 보존.

이 문서 작성 턴의 종료점은 설계 검토 요청이다. 제품 소스·Assets·실행 중 프로세스에는 변경 없음.
