# 창·작업표시줄 발판 인터랙션 — 설계 검토안

상태: 사용자 `ㄱㄱ`로 상세 설계 승인(작업표시줄 자동 숨김/재등장 포함). 구현 계획 작성 단계. 구현·빌드·실행·추가 커밋·푸시 없음.
기준 버전: ordinary rump pull, commit `87e7bb20aee925abcee135703bde46482d136f49`.

## 목표

도로롱을 일반 창의 보이는 윗면 또는 작업표시줄 위에 놓으면 발바닥이 닿게 서고 걷는다. 받치고 있는 창이 움직이면 함께 이동한다. 발판이 없어지면 아래로 떨어져 다음 발판 또는 화면 바닥에 착지한다. 기존 일반 엉덩이 당김, 볼·머리·다리 상호작용과 원본 이미지는 유지한다.

## 접근 선택

- 권장: 창·작업표시줄의 위치/크기/표시 여부/겹침 정보를 읽어 공통 발판 목록을 만든다. 장면 읽기, 발판 판단, 움직임, 화면 표현을 분리한다.
- 단순 대안: 활성 창 하나와 고정 화면 바닥만 사용한다. 구현은 작지만 다른 창과 작업표시줄 자동 숨김을 일관되게 다루기 어렵다.
- 제외: 화면 이미지를 분석해서 창을 찾는다. 이번 기능에 창 내용이나 화면 캡처는 필요하지 않다.

## 첫 구현 범위

1. 일반 창의 실제 보이는 수평 윗면과 작업표시줄의 수평 윗면을 발판으로 취급한다. 최소화·숨김·다른 가상 데스크톱·자기 자신의 창은 제외한다. 겹친 창은 가려지지 않은 구간만 사용한다.
2. 투명 창 크기나 이미지 사각형이 아니라 실제 발바닥 위치로 지지/착지를 판정한다. 기존 걷기/호흡 표현이 발판과의 접촉을 깨뜨리지 않도록 표현 단계에서 발 위치를 맞춘다.
3. 드래그 중에는 기존 사용자 조작이 우선한다. 드래그/기존 놓기 모션의 소유권이 끝난 뒤 발판 지지/낙하로 인계하며 두 동작이 동시에 위치를 갱신하지 않는다.
4. 창을 위·아래·좌·우로 옮기면 도로롱이 그 창에 대한 상대 위치를 유지한다. 발바닥은 접촉을 유지하고 흔들림은 작은 상체 반응으로만 표현한다. 창 크기가 줄어 발판이 없어지거나 발이 끝을 벗어나면 낙하한다.
5. 창 닫기/최소화/가림으로 지지가 사라지면 마지막 실제 표시 위치에서 낙하한다. 아래로 통과한 발바닥 경로에서 처음 만나는 유효 발판에 착지한다. 화면을 벗어나는 무한 낙하나 갑작스러운 위치 초기화는 금지한다.
6. 착지는 짧은 찌부·반동 후 기존 동작으로 돌아온다. 새 캐릭터 이미지는 만들지 않는다.

## 작업표시줄 세부 규칙 — 제안

- 보이는 작업표시줄 위에 서고 걸을 수 있다. 아이콘 클릭과 작업표시줄 자체 동작은 바꾸지 않는다.
- 자동 숨김으로 사라지면 함께 숨거나 보이지 않는 선에 떠 있지 않고, 해당 모니터의 화면 바닥으로 떨어진다.
- 다시 나타나 현재 발 위치와 겹치면 발을 윗면까지 짧고 부드럽게 올린다. 위쪽의 다른 창에 이미 서 있다면 끌어내리지 않는다.
- 작업표시줄의 배치와 표시 상태는 하드코딩하지 않는다. 세로 작업표시줄 면을 수평 발판으로 취급하지 않는다. 캐릭터가 화면 안에 설 공간이 없는 윗면에는 붙이지 않는다.
- 모니터 경계와 배율을 일관된 좌표로 변환한다. 분리된 모니터 사이의 빈 공간이나 다른 모니터의 작업표시줄을 현재 발판으로 오인하지 않는다.

## 구조와 안전

- 읽기 전용 장면 수집: 창 식별자, 영역, 표시 상태, 앞뒤 순서, 모니터 영역, 작업표시줄 영역. 창 제목/내용은 수집·저장하지 않는다.
- 순수한 발판 판단: 가려진 구간 제거, 발 위치와 지지 관계, 낙하 경로 교차를 입력 스냅샷으로 계산한다.
- 움직임 상태: 기존 직접 드래그 / 발판 위 지지 / 낙하 / 착지를 구분한다. 발판 식별자가 사라지거나 바뀌어도 오래된 창 정보를 재사용하지 않는다.
- 표현: 캐릭터 이동과 발 위치 보정, 작은 흔들림, 착지 찌부를 담당한다. UI 갱신마다 모든 창을 무제한 조사하지 않고 장면 수집 빈도와 표시 갱신을 분리한다.
- 일반 앱의 이동·크기·포커스·최소화 상태를 변경하지 않는다. 기존 캐릭터 불투명 영역 외에 새 클릭 차단 영역을 만들지 않는다. 자동 숨김 설정도 변경하지 않는다.
- 일시적 장면 수집 실패와 확인된 발판 소멸을 구분한다. 감지 실패 한 번으로 위치가 튀거나 화면 밖으로 나가지 않게 한다.

## 제외

창 내용 읽기, 앱별 반응, 자율 점프/창 타고 오르기, 가장자리 빼꼼 모션, 창끼리 물리 충돌, 매달림 버전 재도입은 이번 단계에서 하지 않는다.

## 검증 및 인계

장면 필터/겹침/좌표 변환, 발판 이동·크기 변경, 지지 소멸, 빠른 낙하의 발판 통과 방지, 작업표시줄 숨김·재등장, 직접 조작 우선권을 자동 테스트한다. 기존 일반형 회귀 검사와 이미지 동일성을 유지한다.

합성 장면 테스트와 실제 Windows에서의 창 이동·최소화·자동 숨김 테스트는 별도로 기록한다. 실제 앱 미검증을 PASS나 사용자 승인으로 보고하지 않는다. 기존 두 실행본은 보존하며 새 실행본으로 기존 프로세스를 교체하기 전에 대상과 검증 상태를 명시한다.

다음: 승인된 상세 설계를 구현 계획으로 구체화하고 테스트 우선으로 실행한다. 이번 승인은 설계 범위 내 구현 승인이고 추가 commit/push 승인은 아니다.
